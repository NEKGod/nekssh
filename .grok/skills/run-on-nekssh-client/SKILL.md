# 在 NekSSH 客户机上运行并反射端口

NekSSH 桌面端连着这台 SSH 服务器时，会在服务器本机开放一个控制口。你通过它把文件写到用户电脑、在用户电脑上启动进程，并把该进程的端口反射回这台服务器的 `127.0.0.1`。

控制口：`http://127.0.0.1:18765`

只使用这个地址。不要改端口，不要扫描其他端口，不要假设客户机能被公网访问。

## 先确认客户机在线

```bash
curl -fsS http://127.0.0.1:18765/
```

返回 JSON 里 `service` 为 `nekssh` 且 `ok` 为 `true` 才继续。连接失败就停下来，告诉用户先在 NekSSH 里连上这台服务器，并看到顶栏的「反射 http://127.0.0.1:18765」。不要改在服务器上把服务启动起来充数。

## 步骤

1. 确认要运行的程序、启动命令，以及它监听的端口。端口必须是客户机上的 `127.0.0.1` 端口。用户没指定端口时，选一个大于 1024 的空闲端口，并让程序听 `127.0.0.1` 的这个端口。程序若读取环境变量，客户机上的 `PORT` 会设成这个值。
2. 把运行所需的文件写到客户机。路径相对于客户机的 `workspace` 目录，用 `/` 分隔。禁止 `..`。

```bash
curl -fsS http://127.0.0.1:18765/v1/files \
  -H "Content-Type: application/json" \
  -d "{\"files\":[{\"path\":\"app.py\",\"content\":\"print(1)\"}]}"
```

二进制文件把内容放进 `contentBase64`，不要放进 `content`。文件很多时按目录分批提交，每批保持在几十 MB 以内。

3. 在客户机启动，并反射端口。`command` 在客户机的 `workspace` 里执行。`port` 与程序监听端口相同。反射到服务器后，服务器上的访问地址也是 `127.0.0.1` 加这个端口。

```bash
curl -fsS http://127.0.0.1:18765/v1/run \
  -H "Content-Type: application/json" \
  -d "{\"command\":\"python app.py\",\"port\":3000}"
```

4. 读返回 JSON。记下 `id`、`pid`、`local`、`remote`。`ok` 不是 `true`，或存在 `reflectError`，就查看日志并停止这个任务，不要告诉用户已经可以访问。
5. 在这台服务器上访问 `remote` 里的地址，确认服务有响应。再把这个地址告诉用户。
6. 需要输出时读取日志。需要结束时停止任务。停止会结束客户机上的整个进程树。

```bash
curl -fsS http://127.0.0.1:18765/v1/jobs/job-1/log
curl -fsS -X POST http://127.0.0.1:18765/v1/jobs/job-1/stop
```

已有任务列表：

```bash
curl -fsS http://127.0.0.1:18765/v1/jobs
```

## 约束

- 文件只写到客户机 `workspace` 里面。启动命令只做用户要求的那件事。
- 反射端口只供这台服务器本机使用。把 `remote` 地址交给用户，不要把它写成公网地址。
- 同一个端口同一时间只反射一次。端口被占用时，换一个端口重新运行，不要改 NekSSH 的 `18765`。
- 不在客户机上做与用户请求无关的操作。用户要求停止时调用对应任务的 `/stop`。
